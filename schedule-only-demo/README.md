# 工程表のみ｜検証用プロトタイプ

## 解決したい課題

複雑な設定や分析画面より先に、現場の責任者が工程を並べ、日付を調整し、紙に出せるシンプルな工程表に需要があるかを検証します。

## 想定ユーザーと提供価値

工程を作る現場責任者・監督向けです。工程名、担当、開始日、所要日数を入力すると、2週間または4週間の予定が同じ画面の横棒で見えます。スマートフォンでも編集できます。

## 主要機能

- 工程の追加・編集・削除、完了表示
- 工程の並べ替え（パソコンでは持ち手のドラッグ、スマートフォンでは上下ボタン）
- 棒の左右ドラッグによる開始日変更、日付入力による正確な変更
- 2週間／4週間表示、前後移動、今日へ戻る
- スマートフォンの縦向きでは最後に開いた現場と工程表一覧、横向きでは最後に開いた工程表を自動表示。縦向きでも「工程表」タブから閲覧可能
- 複数の工程表を作成し、一覧から開く。最後に開いた工程表を端末内に記憶
- A4横向き印刷・PDF保存、JSONの書き出しと読み込み
- `localStorage`による端末内保存
- 工程の予定棒から領収書写真を撮影・添付し、未添付／確認待ち／確認済みを棒上に表示。領収書の必要性は工程ごとに指定

所要日数は暦日です。土日を薄く表示しますが、作業日数から自動では除きません。遅延時の依存関係再計算、ネットワーク図、ログイン、共同編集、通知はこの別案の検証範囲には含みません。

領収書の写真は端末の IndexedDB に保存され、工程表の JSON 書き出し・PDFには写真本体を含めません。別端末や責任者のブラウザには同期されません。ブラウザのサイトデータを消すと写真も消えるため、原本は別途保管してください。工程と写真の対応は案件 ID と工程 ID で管理し、工程を削除すると紐づく写真も削除します。1工程5枚、1枚8MBまでです。

工程表を開いても画面回転や全画面表示は強制しません。領収書の要否は工程の保存時に確定し、キャンセル時は破棄します。写真の追加・削除と確認済みの変更は即時保存です。

## 技術・セットアップ

HTML / CSS / JavaScriptのみ。依存ライブラリやビルドは不要です。ローカルでは、このディレクトリで `python3 -m http.server 8000` を実行し、`http://localhost:8000/` を開いてください。

この案は `experiment/schedule-only` ブランチの `schedule-only-demo/` にあります。旧版の単一工程表データは、初回起動時に工程表一覧へ移行します。既存の別アプリの案件やログイン情報は取り込みません。書き出したJSONは現在開いている工程表だけです。JSONには工程の情報が入るため、共有先を確認してください。

## 現在の状態と次の検証

工程の作成・編集、保存・再読み込み、印刷ができる単独端末向け試作です。現場の責任者に、紙やExcelの工程表と同じ課題をこの画面で作ってもらい、所要時間、迷った箇所、日付修正の回数を比較します。価値を確認した後に、必要な範囲だけ共同編集や前後関係の計算を検討します。

いずれも画面そのものは複製せず、工程と日付を一度に読み取れる情報設計だけを参考にしています。

## 公開対象と検証

領収書機能は `schedule-only-demo/` と公開用 `docs/` に同じソースを配置しています。GitHub Pagesの配信元設定は別途必要です。`npm test` と `npm run check` はPRのCIでも実行します。画像の端末間同期、OCR、自動仕訳は未実装です。
